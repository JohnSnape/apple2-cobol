# 8  The design tools

Three of the main-menu options are designers. Each works on one screen, takes its commands from the Open-Apple and Solid-Apple keys, and saves its work in a file of its own type. **ESC** always returns to the main menu.

| Option | Designer | Saves |
|---|---|---|
| 2 | FORMAT — screens and records | `NAME.DCT`, and generated COBOL in `NAME.SNP` |
| 3 | QUERY — selecting and sorting records | `NAME.QRY` |
| 4 | REPORT — printed pages | `NAME.RPT`, and generated COBOL in `NAME.SNP` |

The designers share one way of asking questions. A question appears on the bottom line; type the answer and press RETURN. ESC abandons the question, and an Apple-key command typed in answer to a question starts that command instead.

## FORMAT — the screen designer

FORMAT builds a data-entry screen: labels such as `NAME` and the fields the operator types into. The same design also describes a **record** — the fields in order, each with a COBOL name, a type and a width — and that is what makes it the keystone of the system. A program writes records in that layout, QUERY selects records by its fields, and VIEW lists a data file through it.

FORMAT saves the design as a **dictionary**, `NAME.DCT`.

### Placing a field

FORMAT asks five questions for each field, then draws it:

| Prompt | Answer |
|---|---|
| `Row?` | The screen row, **counting from 0** at the top. Rows 0 to 21 may be used. |
| `Column?` | The column where the label starts, counting from 0. |
| `Label?` | The text shown in front of the field, such as `NAME`. Up to fifteen characters. May be left empty. |
| `Name?` | The COBOL data name of the field, such as `CUST-NAME`. Up to ten characters; it is changed to capitals. |
| `Length?` | The field's width on the screen. |
| `Type A/X/N/B?` | **A** letters and spaces · **X** any characters · **N** a number of up to 14 digits · **B** a yes/no flag, typed `Y` or `N`. |

The field begins one space after its label. A field that would overlap another, or run past column 80, is refused with `Field overlaps (key)` or `Bad row/col/size (key)`. A screen may have up to fifteen fields.

The order in which fields are placed is the order of the record, and the order the operator moves through them with TAB. **The fields are numbered from 0** in that order; QUERY and the `QUERY FIELD` statement refer to fields by these numbers.

### How the fields are stored in a record

| Type | Bytes in the record |
|---|---|
| A, X | the field's width, left-justified, space-filled |
| N | 8 — a numeric cell, exactly as a COBOL numeric item is stored |
| B | 8 — a numeric cell holding 1 for Y or 0 for N |

FORMAT works out every offset itself; the dictionary records where each field lies and how long the whole record is. This is the same layout the generated COBOL declares, so a program that writes records through it and the tools that read them always agree.

### Commands

| Key | Action |
|---|---|
| ⌥-S | Save the dictionary. Asks `Save as?`; `.DCT` is added. |
| ⌥-O | Open a dictionary. Asks `Open?`. |
| ⌥-N | Start a new screen. Asks `Clear all? Y/N`. |
| ⌥-D | Delete a field. Asks for its row and column. |
| ⌥-E | Export the screen as COBOL. Asks for a name; `.SNP` is added. |
| ●-C | Show the COBOL that ⌥-E would write. |
| ESC | Return to the main menu. |

A dictionary saved by an earlier version of COBOL SYSTEM is brought up to date when it is opened; save it again to keep the change.

### The generated COBOL

⌥-E writes three pieces of COBOL: the record, a paragraph that paints the labels, and a paragraph that accepts the fields. For a screen named `CUSTSCR` with two fields:

```cobol
* CUSTSCR  generated by FORMAT
*
 01  CUSTSCR-REC.
     05  CUST-NAME  PIC A(20).
* field 0
     05  CUST-BAL  PIC 9(8).
* field 1
*
 CUSTSCR-PAINT.
     DISPLAY "NAME" AT LINE 3 COLUMN 6.
     DISPLAY "BALANCE" AT LINE 5 COLUMN 6.
*
 CUSTSCR-ACCEPT.
     ACCEPT CUST-NAME AT LINE 3 COLUMN 11.
     ACCEPT CUST-BAL AT LINE 5 COLUMN 14.
```

COBOL's `LINE` and `COLUMN` count from 1, so FORMAT's row 2, column 5 becomes `LINE 3 COLUMN 6`. The comment under each `05` gives the field number QUERY uses. A yes/no field is declared `PIC 9 COMP` with an `88` condition-name for Y.

To use the generated code, open the `.SNP` file in the editor (⌥-O, `CUSTSCR.SNP`), move the `01` into the WORKING-STORAGE or FILE SECTION and the two paragraphs into the PROCEDURE DIVISION, write the rest of the program around them, and save it under a new name with `.COB`.

## QUERY — the query designer

A query is a question asked of a file: *which records, in what order*. QUERY builds one by choosing fields from a dictionary, and saves it as `NAME.QRY`. A program runs it with the `QUERY` statement (Chapter 6). Because the program names the query and reads it from the disk when it runs, the question can be changed — balance over 300 instead of over 100 — without recompiling the program.

```
QUERY                                                              CUST.DCT

CONDITIONS
    CUST-BAL   >  100




SORT KEYS
 CUST-NAME    ASCENDING


OA-A Add  OA-D Del  OA-K Key  OA-R UnKey
OA-I Dict  OA-N New  OA-O Open  OA-S Save  ESC Exit
```

### Building a query

1. **⌥-I** and the dictionary name (`Dictionary?`) loads the fields. The name appears top right. Nothing else works until a dictionary is loaded.
2. **⌥-A** adds a condition. It asks:
   - `Field number?` — the field, counting from 0 in dictionary order.
   - `Test = # < ( > ) ?` — one key: `=` equal, `#` not equal, `<` less than, `(` less than or equal, `>` greater than, `)` greater than or equal.
   - `Compare with?` — the value.
   - `Join with A)nd or O)r?` — for every condition after the first, how it combines with those above it.
3. **⌥-K** adds a sort key: `Sort on field number?` and `A)scending or D)escending?`.
4. **⌥-S** saves it (`Save as?`; `.QRY` is added).

A query holds up to eight conditions and four sort keys. ↑ and ↓ select a condition or key; ⌥-D deletes the selected condition and ⌥-R the selected key. ⌥-O opens a saved query and ⌥-N clears the screen.

Conditions on a numeric field compare numbers: `100` matches a balance of 100 however it is stored, and a negative value sorts below zero. Conditions on a text field compare text, with the shorter value padded with spaces. A Y/N field is compared with `Y` or `N`. With no conditions every record is selected; with no sort keys the records come back in file order.

## REPORT — the report designer

REPORT lays out a printed page — 66 lines by 80 columns — and writes the COBOL that prints it. Nineteen page lines show at a time; the rule on row 1 says which page line is at the top and which band it is in.

```
LIST                                                                       CUST
-- PAGE LINE 1 OF 66   BAND HEADING -------------------------------------------
                             CUSTOMER LIST                           ZZ9
                                                                     XXXXXXXX
    NAME                     BALANCE
    -----------------------------------
    XXXXXXXXXXXXXXXXXXXX     ZZZZZZZ9


    TOTAL                    ZZZZZZZZZ9

 ⌥-A Add     ⌥-D Delete    ⌥-G Go to    ⌥-B Band    ⌥-I Dictionary    ESC Exit
 ⌥-N New     ⌥-O Open      ⌥-S Save     ⌥-E Export  ●-C Code
```

| Key | Action |
|---|---|
| ↑ ↓ | Scroll the page a line. |
| ⌥-↑ ⌥-↓ | Scroll a screen. |
| ⌥-G | Go to a page line (`Page line?`). |
| ⌥-I | Bind a dictionary (`Dictionary?`); its name appears top right. Needed before fields and totals. |
| ⌥-A | Add an entry. |
| ⌥-D | Delete the entry at a line and column. |
| ⌥-B | Set a band. |
| ⌥-N | A new, empty report (`Clear the report? Y/N`). |
| ⌥-O | Open a saved report, and its dictionary with it. |
| ⌥-S | Save as `NAME.RPT`. |
| ⌥-E | Export the COBOL as `NAME.SNP`. |
| ●-C | Show the COBOL on the screen, a screenful at a time. ESC stops. |
| ESC | Return to the main menu. |

### Entries

⌥-A asks `Line?` and `Column?` — both counted from 1, as on paper — then `Kind L/R/P/D/F/T?` (one key):

| Kind | Entry | Then asks |
|---|---|---|
| **L** | literal text, up to 32 characters | `Text?` |
| **R** | a rule — one character repeated | `Rule char?` (one key) and `Width?` |
| **P** | the page number | `Picture?` (RETURN gives `ZZ9`) |
| **D** | the date, printed MM/DD/YY | nothing |
| **F** | a field of the dictionary | `Field name?`, and for a number `Picture?` |
| **T** | a total of a number field | `Field name?` and `Picture?` |

A text field prints at its full width. A number field's picture is offered for you — Z's and a 9 for its digits, `.99` for decimals — and RETURN accepts it; type another picture to replace it. A total adds the field from every detail record printed so far, and has two more digits of room. Fields, totals, page numbers and dates are shown in inverse, as `X`s or their picture; literals and rules as they will print. An entry that would overlap another is refused.

### Bands

⌥-B asks `Band H)eading D)etail F)ooting?`, then the first and last page line. RETURN at the first line removes that band.

- **The detail band** prints once for every record. A report must have one.
- **Everything above it** prints at the top of every page — the heading.
- **The footing band** prints at its place on every page, and at the end. A total placed there shows the running total.

When the next detail would run into the footing (or off the page, if there is no footing), the page is finished: the footing is printed, the rest of the page is fed out, and the heading starts the next page.

### The generated COBOL

⌥-E writes `NAME.SNP` in two parts, separated by a line that is a single `*`: the data and the paragraphs. Place them in a program with the editor's ●-P, **R** (Chapter 2) — the data in WORKING-STORAGE, the paragraphs at the end of the PROCEDURE DIVISION.

The data is a group item for every page line that has something on it — `RPT-L05` is page line 5 — with `FILLER` for the spaces and the literals, and a named item for every field, total, page number and date — `R05-30` is page line 5, column 30. There are also the counters `RPT-PAGE` and `RPT-LINES`, an accumulator `RT-nn` for every total, and `RPT-DATE` for the date.

The paragraphs are the whole printing job; your program reads its records and performs them:

| Paragraph | Perform it |
|---|---|
| `RPT-BEGIN` | once, first. It clears the counters and totals, takes the date and prints the first heading. |
| `RPT-DETAIL` | once for every record, with the record's fields in place. It starts a new page when one is needed. |
| `RPT-END` | once, last. It prints the last footing and feeds out the page. |

```cobol
     PERFORM RPT-BEGIN.
     PERFORM PRINT-ONE UNTIL WS-EOF = "Y".
     PERFORM RPT-END.
```

The report prints on the printer whose slot is set in Utilities.
