# 2  Running COBOL SYSTEM

## Starting the system

Start the computer with the COBOL SYSTEM disk. ProDOS loads `COBOL.SYSTEM`, which checks the machine and loads the run-time library, `COBOL.LIB`. If something is missing it says so and waits for a key:

| Message | Meaning |
|---|---|
| `Requires a 65C02 processor - press a key` | The computer is an unenhanced Apple IIe. |
| `Requires a 128K Apple - press a key` | There is no 80-column extended text card. |
| `Cannot load COBOL.LIB - press a key` | The library file is missing or damaged. |

If the system finds a clock it reports `Clock found in slot` *n*. If not, it asks for the date:

```
No clock.  MM/DD/YY?
Time      HH:MM?
```

Type the date as two-digit month, day and year with slashes, and the time in 24-hour form, each followed by RETURN. Pressing RETURN alone leaves the date unset. Files you save are stamped with this date.

## The main menu

```
                               COBOL SYSTEM v1.0                     8/16/2026




                 1) EDIT a New or Existing Program or Template
                 2) FORMAT a Screen for Data Entry or Menu
                 3) Create a QUERY File
                 4) Create a REPORT File

                 5) COMPILE a COBOL Program
                 6) RUN a COBOL Program

                 7) VIEW a Data File
                 8) Utilities
                 9) Exit to ProDOS

                 Choice?
```

Press the number of an option; no RETURN is needed. When the option finishes you return to this menu. `R` is accepted as well as `6` for RUN. Option 9 leaves COBOL SYSTEM through the ProDOS QUIT call.

## Files and their names

Every file COBOL SYSTEM writes carries a three-letter suffix in its ProDOS name, which also sets its file type. When the system asks for a name you may type it with or without the suffix — `PAYROLL` and `PAYROLL.COB` name the same program — except in Utilities, which takes names exactly as they are on the disk.

| Suffix | Type | Contents | Written by |
|---|---|---|---|
| `.COB` | `$47` | COBOL source program | EDIT |
| `.OBJ` | `$4A` | compiled object program | COMPILE |
| `.DAT` | TXT (`$04`) | a relative data file; the record length is in the auxiliary type | your programs |
| `.DCT` | `$49` | a screen dictionary: the screen layout and the record layout | FORMAT |
| `.SNP` | `$48` | COBOL generated from a screen, for your program | FORMAT |
| `.QRY` | `$4D` | a query: conditions and sort keys | QUERY |
| `.RPT` | `$4C` | a report layout | REPORT |

ProDOS names are at most fifteen characters, starting with a letter, using letters, digits and periods. The suffix counts toward the fifteen, so a program name may be up to eleven characters. Names are not case-sensitive. The current ProDOS prefix is shown at the top left of the editor; names without a leading `/` are found there.

## The editor — option 1

```
/COBOL/UNTITLED                                       5,242,720 BYTES AVAILABLE
----------------------------------------------------------- L    12/  140 C  5--






                  (twenty lines of program)






 ⌥-N New     ⌥-O Open   ●-I Insert   ⌥-G Go to   ●-K Ins/Ovr   ESC Exit
 ●-P Place   ⌥-S Save   ●-D Delete   ⌥-P Print   TAB Area B
```

The top line shows the prefix and file name on the left and the free auxiliary memory on the right. The second line is the *rule*: at its right end, `L` is the line the cursor is on and how many lines there are, and `C` is the column. Twenty lines of the program fill the middle of the screen, and the bottom two lines list the commands. Whichever of **Ins** and **Ovr** is in force is shown in inverse.

When a command needs to ask something — a file name, a line number, a choice — the two command lines clear and the question appears there. They come back when the command is finished.

In this manual **⌥** is the Open-Apple key and **●** is the Solid-Apple (Option) key. Hold the Apple key and press the letter.

The editor starts with an empty program called `UNTITLED`. To work on a program you saved before, or on a template, open it with ⌥-O.

### Editor keys

| Key | Action |
|---|---|
| ← → ↑ ↓ | Move the cursor. |
| ⌥-↑ ⌥-↓ | Up or down twenty lines — one screen. |
| ⌥-← | To column 1. |
| ⌥-→ | Just past the last character on the line. |
| TAB | To the next tab stop: columns 1, 5, 9, 13 … TAB from column 1 reaches column 5, Area B. |
| RETURN | Open a blank line below this one and move to it. RETURN does not split a line. |
| DELETE | Rub out the character to the left of the cursor; the rest of the line closes up. |
| ●-I | Insert a blank line above the cursor. |
| ●-D | Delete the line the cursor is on. |
| ●-K | Switch between insert and overtype. The editor starts in overtype. |
| ●-P | Place a FORMAT, QUERY or REPORT into the program, above the cursor (below). |
| ⌥-P | Print the program (below). |
| ⌥-G | Go to a line by number. |
| ⌥-O | Open a program. You are asked `Open?`. |
| ⌥-S | Save the program. You are asked `Save as?`. |
| ⌥-N | Start a new, empty program. You are asked to confirm. |
| ESC | Return to the main menu. The program stays in memory for the compiler. |

A line is eighty characters. The cursor is an inverse block in overtype and an underline in insert mode. In insert mode, typing pushes the rest of the line right and a character pushed past column 80 is lost.

**Saving is safe.** The program is first written to a temporary file (the name plus `.T`); only when that is complete is the old file replaced. If the disk fails partway through, the old file is still there.

**Opening a file from another editor.** Any text file can be opened. Lines longer than eighty characters are cut at eighty; tab characters move to the next tab stop; other control characters are dropped.

### Placing a FORMAT, QUERY or REPORT — ●-P

●-P asks `Place F)ormat, Q)uery or R)eport?` and puts generated COBOL into the program **above the line the cursor is on**; the cursor stays on that line.

**F — a FORMAT.** Asks for the snippet FORMAT exported (`Format (.SNP) to place?` — the name without `.SNP` is enough), then which of its three pieces: `R)ecord, P)aint or A)ccept?`. The record is the `01` and belongs in the DATA DIVISION; the paint and accept paragraphs belong in the PROCEDURE DIVISION, so place each piece with the cursor where it should go. The question offers a default, which RETURN accepts: **Record** above the PROCEDURE DIVISION, **Paint** below it, and **Accept** once the program already holds that screen's paint paragraph.

**Q — a QUERY.** Asks for the query (`.QRY`) and the dictionary it was built on (`.DCT`) — a query file does not record its dictionary — and places the statements that run it:

```cobol
*    QUERY   BIGBAL ON DICTIONARY CUST
     QUERY "BIGBAL" USING "CUST" OF FILE-NAME
         ON ERROR DISPLAY "QUERY FAILED".
     QUERY NEXT GIVING REC-NUMBER
         AT END MOVE "Y" TO END-FLAG.
     QUERY FIELD 0 INTO CUST-NAME
     QUERY FIELD 1 INTO CUST-BAL
```

with one `QUERY FIELD` for every field of the dictionary. Replace `FILE-NAME`, `REC-NUMBER` and `END-FLAG` with your own names (Chapter 6).

**R — a REPORT.** Asks for the report's `.SNP` (exported from REPORT with ⌥-E), then `D)ata or P)aragraphs?` — the default is the data above the PROCEDURE DIVISION and the paragraphs below it (Chapter 8).

### Printing — ⌥-P

⌥-P prints the program on the printer whose slot is set in Utilities (option 6). Each page has the program name, the date and the page number at the top, then sixty numbered lines; the numbers are the line numbers the compiler's messages use. Press ESC to stop between lines. If no printer slot is set the editor says so and nothing is printed.

**Memory.** Each line takes eighty bytes of auxiliary memory. A 128K machine holds about 500 lines; with an expansion card the limit is far beyond any program the compiler can accept. If memory fills while a file is being opened, the editor keeps what it has read and says `Out of memory - press a key`.

## The coding format

COBOL SYSTEM uses all eighty columns of a line, and screen column *n* is source column *n*. There are no sequence numbers.

| Columns | Name | Use |
|---|---|---|
| 1 | Indicator | `*` makes the line a comment. Otherwise leave it blank. |
| 2–5 | Area A | Division and section headers, paragraph names, `FD`, and level numbers `01` and `77`. |
| 6–80 | Area B | Everything else: statements, and the entries under an `01`. |

One TAB from column 1 reaches column 5 and a second reaches column 9, so a statement is two TABs in. A blank line is allowed anywhere.

```
*  A COMMENT LINE
 PROCEDURE DIVISION.
 MAIN-PARA.
     DISPLAY "STATEMENTS START IN AREA B".
```

## Compiling a program — option 5

Choose option 5 straight after leaving the editor. **The compiler reads the program from the editor's memory, not from the disk**, so what it compiles is exactly what you last saw on the screen, saved or not. If there is no program in memory it says:

```
Nothing to compile - EDIT first
```

The compiler works in two passes, loaded one after the other. Pass one reads the IDENTIFICATION, ENVIRONMENT and DATA DIVISIONs; pass two reads the PROCEDURE DIVISION and writes the object file. A successful compile ends:

```
Compiled.  bytes: 333
```

The object file takes the program's name with `.OBJ`: a program saved as `PAYROLL.COB` compiles to `PAYROLL.OBJ`, and one never saved compiles to `UNTITLED.OBJ`.

When the compiler finds an error it stops at the first one and reports the division, the error number, a description and the line:

```
DATA DIVISION error 4 NAME ALREADY IN USE
at line  6
```

Press a key, go back to the editor with option 1, open the program, and use ⌥-G to go to that line. Chapter 7 lists every error.

## Running a program — option 6

Option 6 asks `Program to run?`. Type the name — the `.OBJ` is added for you — and press RETURN. The screen clears and the program runs. When it reaches `STOP RUN` the system says

```
STOP RUN. (Press a Key)
```

and returns to the menu.

If the program does something it cannot finish — divides by zero, uses a subscript outside its table, runs out of memory — it stops with `Run stopped:` and the reason. Chapter 7 lists these. Pressing a key returns to the menu.

## Viewing a data file — option 7

Option 7 shows what a program has written to a data file, without any chance of changing it. It asks `Data file to view?`. For a name such as `CUST` it opens `CUST.DAT` and reads it through the dictionary `CUST.DCT` — the screen you designed for that record in FORMAT:

```
RECORD CUST-NAME            CUST-BAL
0002   AMY                   00000050
0003   EVE                   00001000
0004   CAL                   00000099
```

The first line names the columns. Each record after it is one line: its relative record number, then each field — text as it is stored, numbers as digits, a Y/N field as `Y` or `N`. Deleted records are not shown. A line wider than eighty columns is cut at eighty.

If there is no dictionary of the same name, each record is shown as its raw bytes, with unprintable bytes as dots. If the file cannot be opened the system shows its FILE STATUS (`35` is "not found") and returns to the menu.

The listing appears in the editor, so the arrow keys, ⌥-↑ ⌥-↓ and ⌥-G move about it, but nothing can be typed, deleted, opened or saved. ESC returns to the menu. Because the listing takes the place of a program in memory, choose option 1 and open your program again before compiling.

## Utilities — option 8

```
UTILITIES                                                        Date 11/8/2026
                                                                      Time 10:31
                                                               Printer Slot 1
1) CATALOG a disk
2) COPY a file
3) DELETE a file
4) RENAME a file
5) Set the DATE and TIME
6) Set the PRINTER slot
7) Create a TURNKEY disk
ESC) Back to the menu
```

| Option | |
|---|---|
| 1 CATALOG | Lists the files in the current prefix with their types and sizes. |
| 2 COPY | Asks `Copy which?` and `New name?`. Type both names in full; the new one may be on another disk (`/BACKUP/CUST.DAT`). The copy keeps the file's type. |
| 3 DELETE | Asks `Delete which?` and deletes that file. Type the full name with its suffix. |
| 4 RENAME | Asks `Rename which?` and `New name?`. Type both names in full. |
| 5 DATE and TIME | Asks for the date and time as at startup. On a machine with a clock the clock's own time returns at the next disk operation. |
| 6 PRINTER | Asks `Printer slot (1-7)?` |
| 7 TURNKEY | Makes a disk that runs one program by itself (below). |

The top right of the screen shows the date, the time and the printer slot as they are set now - `not set` and `none` when they are not - and changes as soon as options 5 or 6 change them.

To view a data file, use option 7 of the main menu.

### A turnkey disk

A turnkey disk boots straight into your program, with no menu, editor or compiler on it — the disk to give to the people who use the program.

1. Format a blank ProDOS disk of any size with your usual utility, and note its volume name.
2. Compile the program, so its `.OBJ` is on the system disk.
3. Choose Utilities option 7. Answer `Program for the turnkey disk?` with the program's name, and `Volume of the blank disk (/MYDISK)?` with the volume name.

The system copies six files, showing each as it goes: `PRODOS`, `COBOL.SYSTEM`, `COBOL.LIB`, `COBOL.AUX`, `VM` and the program's `.OBJ`. Data files are not copied — the program creates its own the first time it runs.

When the turnkey disk is started it checks the machine, asks for the date if there is no clock, and runs the program. At `STOP RUN` it shows `STOP RUN. (Press a Key)`, and the key ends the session through ProDOS.

Each utility ends with `Done - press a key` or `ProDOS error $`*nn*, the ProDOS error code in hexadecimal (Chapter 7).
