# 1  Introduction

COBOL SYSTEM is a complete COBOL programming system for the enhanced Apple IIe. Everything you need to write, compile, run and maintain business programs is on one ProDOS disk, reached from one menu:

| Part | What it does |
|---|---|
| **EDIT** | A full-screen, 80-column editor for COBOL source. Holds programs of thousands of lines in auxiliary memory. |
| **FORMAT** | A screen designer. You place labels and fields on a screen; it saves the layout as a *dictionary* and writes the COBOL to display and accept it. |
| **QUERY** | A query designer. You pick conditions and sort keys from a dictionary's fields and save them as a *query* a program can run. |
| **REPORT** | A report designer. You lay out a printed page. |
| **COMPILE** | A two-pass compiler that turns a COBOL program into a compact object file. |
| **RUN** | The interpreter that executes an object file, with the run-time library behind it. |
| **VIEW** | Shows the contents of a data file, laid out by its dictionary, without any risk of changing it. |
| **Utilities** | Catalog, copy, delete and rename files, set the date and time, choose a printer. |

The language is a subset of ANSI standard COBOL, chosen for business work on a small machine: relative files, exact decimal arithmetic to fourteen digits, edited pictures for money and dates, and the structured statements (`END-IF`, `EVALUATE`, in-line `PERFORM`) that make a COBOL program readable. One statement, `QUERY`, is an extension: it selects and sorts records using a query built in the QUERY designer.

## Hardware and software required

| | |
|---|---|
| Computer | An **enhanced Apple IIe** (65C02 processor), or an Apple IIc or IIGS. The system checks for the 65C02 when it starts and will not run without it. |
| Memory | **128K** — a IIe with an 80-column extended text card. More auxiliary memory, such as a RamWorks card, is used automatically: it holds longer programs and more records. |
| Display | An 80-column monitor. |
| Disk | A ProDOS hard disk or large volume. The system and its files fit on an 800K disk; a 32 MB volume, such as one on a BOOTi or similar card, leaves room for your work. |
| Clock | Optional. With a ProDOS clock or a No-Slot Clock the system stamps the date on everything; without one it asks for the date when it starts. |
| Printer | Optional. Any printer interface card; Utilities sets which slot. |

COBOL SYSTEM runs under **ProDOS 8** and replaces BASIC: when the disk starts, the system's own menu appears.

## How a program is built

A COBOL program goes through four steps, all from the main menu:

1. **Write it** in EDIT (option 1) and save it. The file is named `NAME.COB`.
2. **Compile it** (option 5). The compiler reads the program straight from the editor's memory, checks it and writes `NAME.OBJ`. If anything is wrong it stops with an error number, a description and the line.
3. **Run it** (option 6). The interpreter loads `NAME.OBJ` and executes it. Output appears on the screen; files are read and written on the disk.
4. **Look at what it made** with VIEW (option 7), which lists a data file one record to a line.

Screens, queries and reports are designed with FORMAT, QUERY and REPORT and come into a program as COBOL text or, for a query, by name at run time.

## COBOL programming concepts

COBOL (COmmon Business-Oriented Language) was designed in 1959 so that business programs could be read by the people who used them as well as by the programmers who wrote them. A COBOL statement reads like an English sentence:

```cobol
     MULTIPLY HOURS-WORKED BY HOURLY-RATE GIVING GROSS-PAY.
```

Three ideas run through the language:

- **Data is described before it is used.** Every field a program touches is declared in the DATA DIVISION with a *picture* that says what it holds — `PIC X(20)` is twenty characters, `PIC 9(5)V99` is a number with five digits before an assumed decimal point and two after.
- **Arithmetic is decimal.** Money is added in dollars and cents, exactly, with no binary rounding. COBOL SYSTEM keeps every number to fourteen digits.
- **Records live in files.** A program reads a record into an area described in the DATA DIVISION, works on its fields by name, and writes it back.

## The four divisions of a COBOL program

Every program has four divisions, always in this order:

| Division | What it contains |
|---|---|
| `IDENTIFICATION DIVISION` | The program's name. |
| `ENVIRONMENT DIVISION` | The files the program uses and a few settings for this machine. May be left out if the program uses no files. |
| `DATA DIVISION` | The layout of every record and every working field. |
| `PROCEDURE DIVISION` | The statements, grouped into paragraphs. |

The smallest complete program:

```cobol
 IDENTIFICATION DIVISION.
 PROGRAM-ID. HELLO.
 PROCEDURE DIVISION.
 MAIN-PARA.
     DISPLAY "HELLO FROM THE APPLE IIE".
     STOP RUN.
```

Chapters 3 to 6 describe each division in turn.

## How COBOL SYSTEM differs from a mainframe COBOL

Experienced COBOL programmers should read this list before Chapter 3.

- **Source lines have no sequence numbers.** Column 1 is the indicator column, Area A begins at column 2 and Area B at column 6. See Chapter 2.
- **Every numeric item occupies eight bytes** in memory and in a record, whatever its PICTURE: a sign byte and fourteen packed decimal digits. `COMP` and `COMP-3` are accepted and change nothing. A record layout counts eight bytes for each numeric field.
- **Files are relative** — records found by number. There are no indexed files.
- **Two files** may be declared in one program.
- **There is no floating point**, and no `CALL`; a program is a single object file.
- **`QUERY`** is an extension for selecting and sorting records.
