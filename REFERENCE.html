1. The shape of a source line

No sequence numbers and no identification field. Eighty columns, all of them text.

col 1     indicator     * = comment,  - = continuation
col 2-5   Area A        division, section, paragraph and FD names,
                        level 01 and 77
col 6-80  Area B        everything else

TAB moves 4 columns, which is exactly the Area A → Area B step. EDIT shows no line number, because screen column n is source column n.

A word is up to 30 characters of A-Z 0-9 -, not starting or ending with a hyphen. Case is not significant. A literal is "..." or '...'; a figurative constant is a word. A statement ends at a full stop, and a full stop is required at the end of a paragraph.

2. IDENTIFICATION DIVISION

       IDENTIFICATION DIVISION.
       PROGRAM-ID. LEADS.

AUTHOR, DATE-WRITTEN, INSTALLATION, SECURITY, REMARKS — taken and ignored. Everything up to ENVIRONMENT DIVISION or DATA DIVISION is free text: words, numbers and punctuation are all skipped.

The case setting is the one clause here that makes code: a program that says ANYCASE gets a one-instruction CASE at its start. The case of the source is never significant — keywords and names may be written in either, and text in quotes is kept as written.

Anything else is error 50, NOT PART OF THIS COBOL, at its line — ORGANIZATION INDEXED, RECORD KEY, ALTERNATE, LINE SEQUENTIAL, I-O-CONTROL, SAME AREA. Until 2026-11-12 such words were skipped, and the program ran as something other than what it said.

Every numeric variable is the same eight bytes, whatever its PICTURE says and whether you write COMP-3 or not: a NUM8 cell, sign in a flag byte, fourteen digits. COMP-3 is a hint about intent, not a layout request — it changes nothing about the storage. One size means one ADD, one COMPARE, one MULTIPLY, and no length parameter anywhere in the runtime.

4.1 PICTURE characters

9a digit
Xany character
Aa letter or space
Ssigned — the sign is in the flag byte, not in the digits
Vassumed decimal point, takes no room
Pscaling position
Zdigit, leading zeros to spaces
*digit, leading zeros to asterisks (cheque protection)
$currency, fixed or floating
+ -sign, fixed or floating
, .separator and point
/ B 0insert a slash, a space, a zero
CR DBcredit / debit, printed only when negative

(n) repeats: PIC X(20), PIC S9(6)V99. All of the above are built — PICTURE.S does both directions, edit and de-edit.

COMP-1, COMP-2 (no floating point anywhere in this system), 66 RENAMES, OCCURS DEPENDING ON, INDEXED BY, INDEX, POINTER, EXTERNAL, GLOBAL, LINKAGE SECTION, REPORT SECTION, SCREEN SECTION — ✘, error 50 at the line. SYNC / SYNCHRONIZED, USAGE DISPLAY, BINARY, PACKED-DECIMAL and every COMP-n but 1 and 2 are taken: a number is a NUM8 cell whatever its usage says.

SCREEN SECTION is dropped on purpose. FORMAT paints the screen and generates ordinary DISPLAY/ACCEPT ... AT LINE n COLUMN n you can read and edit. No new grammar, no new p-code, and nothing hidden.

9. PROCEDURE DIVISION — files

All of these work — RECMAN.S in the library, the opcodes in the interpreter, and the verbs in the compiler — except where a row says not.

Statement
OPEN INPUT / OUTPUT / I-O / EXTEND✔one file per statement
CLOSE✔
READ / READ ... NEXT RECORD✔
WRITE / REWRITE / DELETE✔WRITE names the RECORD, not the file
START ... KEY IS✔
AT END / INVALID KEY✔tests FILE STATUS, branches. On READ, READ NEXT, WRITE, REWRITE, DELETE. A REWRITE or DELETE of a deleted record, or past the end, is "23" (FIXLIST A20, fixed 2026-11-20)
NOT AT END / NOT INVALID KEY✘not built yet: error 12. Test the flag after END-READ instead

A relative file is arithmetic, not a structure. Record n lives at byte (n−1) × record-length and nowhere else — no index, no free list, nothing inside the file but records. Three things follow that a programmer should know:

  • Keys are 1-based. RELATIVE KEY 1 is the first record, as the standard says.
  • The record length lives in the file, in its ProDOS aux field — the same place BASIC.SYSTEM puts it for OPEN name,L128. A .DAT is an ordinary TXT file with its record length in aux. Only OPEN OUTPUT needs you to say what the length is, because a file that does not exist yet cannot be asked.
  • Two files open at once. There are three ProDOS buffers and the catalog keeps one, so a program with two SELECTs can still let the operator pick a file.

9.1 FILE STATUS values

Two characters, as the standard says, and the same shape as CRT STATUS.

"00"it worked
"10"end of file — this is what AT END tests
"23"no such record: past the end, key 0, or deleted - for READ, REWRITE and DELETE alike
"24"write outside the file's boundary
"30"a ProDOS error that has no better name
"31"OPEN and the name breaks ProDOS's rules: each part 1-15 characters, a letter first, then letters, digits and periods; 64 in all. Refused, never changed - MY FILE!.DAT is not opened as anything else
"34"reserved for "no room"; nothing raises it. Rewriting a record past the end is "23"
"35"OPEN and the file is not on the disk
"37"wrong mode — writing to an INPUT file, say
"41"already open
"42"not open

DELETE writes one byte. A deleted record is one whose first byte is $FF; the rest keeps whatever it held. The space cannot be returned to ProDOS in any case — record n has to stay at byte (n−1) × reclen whatever happens to its neighbours — and READ NEXT skips deleted records rather than returning them.

One thing version 1 does not do. Writing record 500 to a file that holds 10 extends it, and the 490 records in between read back as all zeros rather than as deleted. Write records in order — which is what ADD 1 TO WS-LAST then WRITE does, and what all three sample programs do — and the gap never exists.

10. PROCEDURE DIVISION — QUERY

One verb, four forms. It runs a .QRY file built in the QUERY designer (menu option 6) against records in auxiliary memory, and hands back the ones that match, in the order the query asked for.

       QUERY "ACTIVE" USING "CUSTOMER" FOR 500
           GIVING HOW-MANY
           ON ERROR PERFORM QUERY-FAILED.
       PERFORM SHOW-ONE UNTIL ALL-DONE.
      *
       SHOW-ONE.
           QUERY NEXT GIVING REC-NUMBER
               AT END MOVE "Y" TO WS-DONE.
           IF NOT ALL-DONE
               QUERY FIELD 0 INTO CUST-NAME
               QUERY FIELD 3 INTO CUST-BALANCE
               DISPLAY CUST-NAME " " CUST-BALANCE
           END-IF.
Statement
QUERY q USING d FOR n✔run it over records 0..n−1 in aux memory
QUERY q USING d OF file✔over a relative file; deleted records are skipped. Status 5 if the file is not there
... GIVING count✔how many records matched
... ON ERROR✔taken when the status is not zero
QUERY NEXT✔step to the next hit
... GIVING rec✔the record number of this hit
... AT END✔taken when the hits run out
QUERY SORT✔re-sort the hits you already have
QUERY FIELD n INTO x✔field n of the current record

USING is not optional. A query names its fields by number, and a number means nothing without the dictionary it was built against — which the .QRY file has no room to record. Name the same .DCT the designer used.

Field numbers start at zero and run in dictionary order — which is the order the COPY copybook FORMAT writes declares them, so field n is the *n*th 05.

10.1 Where the two files come from

This is the one place in the system where a designer's output does not come in through COPY, and it is worth understanding once:

the record — names, widths, the items you read intoCOPY CUSTOMER. — compiled in, from FORMAT
the question — which records, in what order"ACTIVE", read off the disk when the statement runs

So changing the question needs no compiler: somebody opens the QUERY designer, changes balance over 300 to balance over 500, saves, and the next run selects differently. That is the point of it — and the thing to be careful about, because the program no longer contains its own answer.

10.2 QUERY STATUS codes

0ok
1more hits than the cursor can hold
2the query file holds something we do not understand
3no room for the cursor in that bank
4too many sort keys, or a composite key over 20 bytes
5OF file-name, and RECMAN.S is not built
6the query's conditions do not make sense together
7not a .QRY file, or too big
8a field number the dictionary does not have
9the USING dictionary could not be read

SORT and SELECT are not verbs — see the exclusions below. The engine behind QUERY is SELECT.S and SORT.S in the library, and it never moves a record: a result is a list of record numbers.

11. Source text — COPY

       WORKING-STORAGE SECTION.
           COPY CUSTSCR.
           COPY "1/LEDGER".
       PROCEDURE DIVISION.
           ...
           COPY CUSTSCR.
           COPY DATES.
COPY name. / COPY "name".✔the compiler reads the file and compiles its lines in place of the statement (2026-11-11)
COPY ... OF / IN library-name✘error 44 — write a prefix or a path instead: COPY "*/PROCS/DATES".
COPY ... REPLACING✘error 44
REPLACE✘

Not a verb — a compiler directive, with no runtime existence whatsoever. It is how a generated screen or report gets into a program: FORMAT re-exports, you recompile, and the program has the new layout with no editing. A placed snippet is a snapshot; COPY is a live reference.

A .SNP is copied by division. FORMAT, REPORT and the procedure library write one .SNP in pieces parted by lines that are a lone * — the notes, then the data, then the paragraphs, the same pieces SA-P places. COPY takes the piece that fits where it is written: in the DATA DIVISION the data (between the first lone * and the second), in the PROCEDURE DIVISION the paragraphs (everything after the second). So the same COPY CUSTSCR. is written twice, once in WORKING-STORAGE and once among the paragraphs. A file with no lone * is copied whole, wherever it is.

Where it looks. A name with no suffix gets .SNP. A bare name is looked for in 0/ and then in */PROCS/, so COPY DATES. finds the library. A name with a / in it — a prefix name like "1/LEDGER" or a full path — is used as written, and has to be quoted.

The rules. COPY nests one deep: a copybook may not contain a COPY (error 45). COPY ends its line — anything after its full stop is not read. A PROCEDURE DIVISION header may not come out of a copybook (error 47). A copybook's lines go into auxiliary memory after the program's; if there is no room, error 46. An error inside a copybook is reported at the COPY's line, with the line in the book: at line 10, COPY book line 2.

Error
43COPY BOOK NOT FOUND
44WRITE COPY, A NAME, A FULL STOP
45COPY INSIDE A COPY BOOK
46NO ROOM FOR THE COPY BOOK
47PROCEDURE DIVISION IN COPY BOOK

Two more errors, not COPY's: 49 PROGRAM AND DATA OVER 7,680 BYTES — the object and its WORKING-STORAGE must fit between $9200 and the file buffers at $B000; and 50 NOT PART OF THIS COBOL — a clause, section or level this compiler does not have.

12. The Apple command keys

Not written yet — CRT STATUS IS is error 50 until it is (FIXLIST B). The runtime keeps the two bytes below; the clause that names a field for them is what is missing. As designed, SPECIAL-NAMES. CRT STATUS IS ws-item. gives you a two-character field that says how the last ACCEPT ended:

First character
"0"RETURN
"1"ESC
"2"TAB
"3"Open-Apple + the key in the second character
"4"Solid-Apple
"5"both
       01  KEY-STATUS.
           05  KEY-HOW    PIC X.
               88  ENTERED   VALUE "0".
               88  CANCELLED VALUE "1".
           05  KEY-CHAR   PIC X.

           ACCEPT CUST-NAME AT LINE 5 COLUMN 20.
           EVALUATE KEY-STATUS
               WHEN "3P"  PERFORM PRINT-THE-LIST
               WHEN "3Q"  PERFORM FINISH
           END-EVALUATE.

Acting on a command key needs no new keyword — EVALUATE already does it. A program that never declares a CRT STATUS never sees a command key, and OA-P simply types a P.

OA-Ctrl-Reset reboots the machine and nothing can intercept it. KEYS.md is the full contract.

14. The procedure library

SA-P, P, then a name: DATES, TEXT, SCREEN, MONEY or WORDS, from the PROCS folder (a name starting with / is used as it is). Place it twice — Data in WORKING-STORAGE, Paragraphs at the end of the PROCEDURE DIVISION; the default answer is the one that fits where the cursor is. Or write COPY DATES. in both places instead, and the compiler reads it from the library every time (see COPY, above). The notes at the top of each .SNP say what each paragraph does and what it costs.

15. A report on the screen, a page at a time

           DISPLAY "P)rint or S)creen?" ACCEPT ANS FROM KEY.
           IF ANS = "S" SET PRINTER TO SCREEN.
           PERFORM RPT-BEGIN.
           ...
           PERFORM RPT-END.
           SET PRINTER TO PAPER.

The same REPORT paragraphs print or show. On the screen every report page starts on a clear screen, a page longer than the screen stops when it is full, and every stop says Press a key to go on. The blank lines REPORT pads a page with on paper never reach the screen.

16. Menus

FORMAT, OA-M: each line is a row, a column and up to 72 characters of text. A line written 1) Add a contact or A) Add answers to the key before the ); any other line is a title. Each key may be used once: a second Q) (or q), since keys are upper cased) is refused with Key already used, and the compiler stops a .MNU made elsewhere that has one key twice (error 42, MENU KEY USED TWICE). OA-S saves NAME.MNU (type $4E MNU) and asks whether to centre it; OA-O NAME.MNU opens it again; OA-D takes out the lines on a row. In a program:

           ACCEPT CHOICE FROM MENU "MAIN".
           EVALUATE CHOICE
               WHEN "1" PERFORM ADD-CONTACT
               WHEN "Q" GO TO FINISH
           END-EVALUATE.

Letters come back upper case; any key that is not on the menu rings the bell. The menu is read when the program is compiled — change the .MNU, compile again.

17. Prefixes

ProDOS 16's idea: a name may start with a prefix name.

*/the boot prefix — where COBOL.SYSTEM is. Set at boot; nothing can change it
0/the program prefix — ProDOS's current prefix, where programs and objects live
1/ to 9/for data and anything else: 1/CUST.DAT

Anywhere a file is named — ASSIGN TO "1/CUST.DAT" (or a data name holding 1/CUST.DAT), EDIT's open and save, FORMAT, QUERY, RUN, Utilities — the prefix name is replaced by the directory it holds. Utilities 8 sets them and saves them with the printer slot in */COBOL.SETTINGS, read at boot; a program can set them for the session with SET PREFIX. The system's own files always come from */.

19. The one-page summary

Most of COBOL is free. Two entire divisions and nearly all of the DATA DIVISION are compile-time only; the runtime cost of the whole language is concentrated in about fifteen verbs.

What is still missing is FIXLIST.md's list B, and each row above marked ✘ says so. (This section used to list GIVING, the PERFORM forms, the class tests, FROM DATE / TIME, UPON PRINTER and QUERY ... OF as traps; all of them have been built and tested since.)

The limits a program meets first (2026-11-11): 128 names (data names, 88-levels, file names and paragraph names together), each up to 30 characters, all of them significant — a longer one is refused (error 48), never cut short; 128 data items (error 2); and 2,048 bytes of literals — a quoted literal costs its length, every numeric literal 9 bytes (a NUM8 cell), and a repeated one is stored once. Names exist only while compiling: the finished program has item numbers, so a long name costs it nothing.
